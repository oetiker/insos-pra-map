  <action>
Create the upstream data fetching and transformation layer:

1. Create `server/odata-client.js`:
   - Import dotenv is not needed (loaded in index.js)
   - Export `fetchProviders()` — fetches PrA providers from OData:
     ```
     GET {ODATA_BASE}/Adresse?$filter=AdressTypValue eq 0 and AnzahlAdressePraktischeAusbildungList gt 0&$select=Id,Firma,AktuelleStrasseUndNummer,AktuellerOrtUndPLZ,AktuelleAdresse,AnzahlAdressePraktischeAusbildungList&$expand=AdressePraktischeAusbildungList&$format=json
     ```
   - Export `fetchPraLookup()` — fetches PrA profession reference data:
     ```
     GET {ODATA_BASE}/PraktischeAusbildung?$select=Id,Bezeichnung&$format=json
     ```
   - Read ODATA_BASE from `process.env.ODATA_BASE` with fallback to `https://performx.artiset.ch/odata`
   - Set User-Agent header: `INSOS-PrA-Map/1.0 (+https://github.com/oetiker/insos-map)`
   - Implement in-memory cache with TTL from `process.env.CACHE_TTL` (default 86400000 = 24h):
     - Store `{ data, timestamp }` for each endpoint
     - Return cached data if `Date.now() - timestamp < TTL`
     - On fetch failure, return cached data if available (stale-on-error), log the error
   - Export `clearCache()` for testing purposes
   - Both functions return the `value` array from the OData response (`json.value`)

2. Create `server/normalizer.js`:
   - Export `normalizeProviders(rawProviders, praLookup)`:
     - `rawProviders` = array from fetchProviders()
     - `praLookup` = array from fetchPraLookup(), used to build `{ id -> name }` map
   - For each raw provider, produce:
     ```json
     {
       "id": raw.Id,
       "name": raw.Firma,
       "street": raw.AktuelleStrasseUndNummer,
       "plzOrt": raw.AktuellerOrtUndPLZ,
       "fullAddress": raw.AktuelleAdresse (replace \r\n with \n),
       "lat": null,
       "lon": null,
       "approximate": false,
       "praOfferings": [{ "id": praId, "name": lookupMap[praId] || "Unknown" }],
       "praCount": raw.AnzahlAdressePraktischeAusbildungList,
       "website": null,
       "phone": null,
       "email": null
     }
     ```
   - The `praOfferings` array is built by mapping `raw.AdressePraktischeAusbildungList` entries, looking up `PraktischeAusbildungId` in the praLookup map to get the profession `Bezeichnung` (name)
   - Include `website`, `phone`, `email` as null placeholders — these will be populated in a later phase when contact info access is resolved (per RESEARCH.md Open Question 1)
   - lat/lon are null at this stage — geocoding fills them in (Plan 02)
   - Filter out any providers where both street and plzOrt are empty/null (unlikely but defensive)
  </action>
  <verify>
Create a quick test: `node -e "import('./server/odata-client.js').then(m => m.fetchProviders().then(d => console.log('Providers:', d.length)))"` — should print approximately 365.
