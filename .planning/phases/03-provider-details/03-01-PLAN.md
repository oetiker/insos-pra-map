<task type="auto">
  <name>Task 1: Fetch Kommunikationsmittel contact data in build pipeline</name>
  <files>server/odata-client.js, server/normalizer.js, scripts/build-data.js</files>
  <action>
1. **server/odata-client.js** — Add `fetchKommunikationsmittel(providerIds)` function:
   - Accept an array of provider ID strings (GUIDs)
   - Batch into groups of 20 IDs per request to stay within URL length limits
   - For each batch, build an OData `$filter` using `or` chains: `(AdresseId eq {id1} or AdresseId eq {id2} ...) and IstAktiv eq true`
   - `$select`: `AdresseId,KommunikationstypValue,Wert`
   - `$format`: `json`
   - Fetch from `${ODATA_BASE}/Kommunikationsmittel?${params}` with the same User-Agent header used by other functions
   - Accumulate all `json.value` items across batches into a single array
   - Add 200ms delay between batch requests (politeness)
   - Return the accumulated array of Kommunikationsmittel records
   - No caching needed (this runs once at build time)
   - Export the function

   **IMPORTANT:** Do NOT use OData `$expand=Kommunikationsmittel` on Adresse (returns HTTP 400). Do NOT use the `in` operator (returns HTTP 400). Use `or` chains only.

2. **server/normalizer.js** — Add `joinContactData(providers, kommunikationsmittel)` function:
   - Accept the array of normalized providers and the array of Kommunikationsmittel records
   - For each provider, filter Kommunikationsmittel records by matching `AdresseId === provider.id`
   - Map `KommunikationstypValue` to contact fields:
     - Type 0 = email
     - Type 1 = phone (landline, preferred)
     - Type 2 = mobile (fallback if no type 1)
     - Type 3 = website
     - Type 10 = billing email (IGNORE — not user-facing)
   - Take the first record per type (primary/oldest)
   - Set `provider.email`, `provider.phone`, `provider.website` from the mapped values (or leave null if missing)
   - Mutate providers in-place and return the array
   - Export the function

3. **scripts/build-data.js** — Add contact data fetch step to the pipeline:
   - Import `fetchKommunikationsmittel` from `../server/odata-client.js`
   - Import `joinContactData` from `../server/normalizer.js`
   - After `normalizeProviders()` call and before `geocodeAll()`, extract provider IDs: `const providerIds = normalized.map(p => p.id)`
   - Call `const kontakt = await fetchKommunikationsmittel(providerIds)`
   - Call `joinContactData(normalized, kontakt)`
   - Add console.log for progress: `Fetched contact data for N providers`
   - The geocoding and JSON output steps remain unchanged

4. **Rebuild data** — Run `npm run build:data` to regenerate `src/public/data/providers.json` with contact fields populated.

5. **Verify** — Check that providers.json now has non-null email/phone/website for the majority of records (research showed 10/10 sampled providers had all three). Log any providers with missing fields to console for awareness.

  <files>src/map.js, src/style.css</files>

1. **src/map.js** — Add popup builder function and update marker creation:

   a. Add an `esc(str)` function for HTML escaping (replace `&`, `<`, `>`, `"` with HTML entities). Return empty string for falsy input.

   b. Add `buildPopupContent(provider)` function that generates the popup HTML:
      - Wrap everything in `<div class="provider-popup">`
      - Organization name: `<strong>` tag with escaped `provider.name`
      - Address: `<p class="provider-popup-address">` with escaped `provider.street` + `<br>` + escaped `provider.plzOrt`
      - Phone (if not null): `<p>` with `<a href="tel:{phone}">` showing the phone number. Use `tel:` scheme for mobile click-to-call.
      - Email (if not null): `<p>` with `<a href="mailto:{email}">` showing the email address.
      - Website (if not null): `<p>` with `<a href="{website}" target="_blank" rel="noopener">` showing the URL with `https://` prefix and trailing `/` stripped for display.
      - INSOS link: `<p class="provider-popup-insos">` with `<a href="https://www.insos.ch/de/ueber-uns#unsere-mitglieder-268211" target="_blank" rel="noopener">INSOS Mitgliederverzeichnis</a>`.
      - All provider data MUST be HTML-escaped via `esc()` before insertion (XSS prevention — data is from external API).

   c. In the marker creation loop, replace the current `marker.bindPopup(\`<strong>${provider.name}</strong>\`)` with `marker.bindPopup(buildPopupContent(provider))`.

2. **src/style.css** — Add popup styling rules:

   ```css
   .provider-popup { font-size: 14px; line-height: 1.4; }
   .provider-popup strong { font-size: 15px; display: block; margin-bottom: 4px; }
   .provider-popup-address { color: #555; margin: 4px 0; }

   ```
   This ensures readable text sizing, proper spacing between contact lines, word-wrapping for long URLs/emails (prevents horizontal overflow on mobile), and a visual separator before the INSOS link.
