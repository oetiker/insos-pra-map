**Create src/hash-state.js** with two exported functions:

```javascript
/**
 * Write current app state to URL hash without creating a history entry.
 * Uses short keys (s, p, lat, lng, z) to keep URLs compact.
 * @param {string} sector - Current sector filter value (empty string = all)
 * @param {string} profession - Current profession filter value (empty string = all)
 * @param {L.Map} map - Leaflet map instance
 */
export function writeHash(sector, profession, map) {
  const p = new URLSearchParams();
  if (sector) p.set('s', sector);
  if (profession) p.set('p', profession);
  const c = map.getCenter();
  p.set('lat', c.lat.toFixed(4));
  p.set('lng', c.lng.toFixed(4));
  p.set('z', String(map.getZoom()));
  history.replaceState(null, '', '#' + p.toString());
}

/**
 * Read app state from URL hash. Returns null if no hash present.
 * @returns {{ sector: string, profession: string, lat: number, lng: number, z: number } | null}
 */
export function readHash() {
  const raw = location.hash.slice(1);
  if (!raw) return null;
  const p = new URLSearchParams(raw);
  return {
    sector: p.get('s') || '',
    profession: p.get('p') || '',
    lat: p.has('lat') ? parseFloat(p.get('lat')) : NaN,
    lng: p.has('lng') ? parseFloat(p.get('lng')) : NaN,
    z: p.has('z') ? parseInt(p.get('z'), 10) : NaN
  };
}
```

2. **On page load -- restore hash state:** After data is loaded and filters are initialized, check for hash state BEFORE the default fitBounds. The `initFilters` function from 05-01 returns `{ sectorSelect, profSelect }`. Use these to programmatically set dropdown values:

```javascript
const { sectorSelect, profSelect } = initFilters(data.providers, onFilterChange);

// Restore state from URL hash (if present)
const hashState = readHash();
if (hashState) {
  // Restore filter selections
  if (hashState.sector) {
    sectorSelect.value = hashState.sector;
    sectorSelect.dispatchEvent(new Event('change'));  // triggers profession dropdown population
    if (hashState.profession) {
      profSelect.value = hashState.profession;
      profSelect.dispatchEvent(new Event('change'));  // triggers marker filtering
    }
  }
  // Restore map position (only if valid lat/lng/zoom)
  if (!isNaN(hashState.lat) && !isNaN(hashState.lng) && !isNaN(hashState.z)) {
    map.setView([hashState.lat, hashState.lng], hashState.z);
  }
}
```

Note on Pitfall 2 from research: The map is already initialized with `initMap('map', [])` (from 05-01 refactor) which calls `map.fitBounds(SWISS_BOUNDS)`. After hash state restoration, `map.setView()` overrides the fitBounds. This is correct -- the map briefly shows Swiss bounds then jumps to hash position. If this flash is noticeable, an alternative is to modify `initMap` to accept optional initial view params, but test first since it may not be visible given async data loading.

5. **Circular event prevention (Pitfall 3):** The `hashchange` event listener is NOT needed for this implementation. Filter changes and map moves call `writeHash` directly (using `replaceState`). The only case where `hashchange` fires is browser back/forward, but since we use `replaceState` (not `pushState`), there are no history entries to navigate between. Therefore, do NOT add a `hashchange` listener -- it would only risk circular loops with no benefit.

6. **Ensure initial hash is written:** After everything is wired (filters, map, hash restore), if there was no hash state on load, write the initial state so the URL immediately becomes shareable:

```javascript
  });
}
```

This uses `map.once('moveend')` because `fitBounds` is asynchronous and the final map position isn't known until the animation completes.
