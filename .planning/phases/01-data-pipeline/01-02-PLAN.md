  <action>
Build the geocoding subsystem with persistent SQLite cache:

1. Create `server/geocode-cache.js`:
   - Import `Database` from `better-sqlite3`
   - Create/open database at `./data/geocode-cache.sqlite`
   - Ensure `data/` directory exists (use `fs.mkdirSync` with `recursive: true`)
   - Set `pragma journal_mode = WAL` for performance
   - Create table if not exists:
     ```sql
     CREATE TABLE IF NOT EXISTS geocodes (
       address TEXT PRIMARY KEY,
       lat REAL,
       lon REAL,
       approximate INTEGER DEFAULT 0,
       created_at TEXT DEFAULT (datetime('now'))
     )
     ```
   - Prepare statements for get and set (compiled once)
   - Export `getCachedGeocode(address)` — returns `{ lat, lon, approximate }` or null
   - Export `setCachedGeocode(address, lat, lon, approximate)` — upserts into cache
   - The `approximate` field: 0 = street-level precision, 1 = city/PLZ center fallback

2. Create `server/geocoder.js`:
   - Import getCachedGeocode, setCachedGeocode from geocode-cache.js
   - Read GEO_API from `process.env.GEO_API` with fallback to `https://api3.geo.admin.ch/rest/services/api/SearchServer`
   - Helper: `sleep(ms)` — returns a promise that resolves after ms milliseconds
   - Export `geocodeAddress(street, plzOrt)`:
     - Compose address string: `${street}, ${plzOrt}`
     - Check cache first — return immediately if hit
     - Call geo.admin.ch with: `searchText=${street} ${plzOrt}`, `type=locations`, `origins=address`, `sr=4326`, `limit=1`
     - If results found: cache with approximate=false, return `{ lat, lon, approximate: false }`
     - If no results: fallback to PLZ/Ort only — call with `searchText=${plzOrt}`, `origins=zipcode`
     - If fallback found: cache with approximate=true, return `{ lat, lon, approximate: true }`
     - If both fail: log warning, return null (provider will have null coordinates)
   - Export `geocodeAll(providers)`:
     - Iterate sequentially over all providers
     - Skip providers that already have lat/lon set
     - For each provider needing geocoding, call geocodeAddress and assign lat/lon/approximate
     - Sleep 100ms between geocoding calls (politeness: max 10 req/sec to geo.admin.ch)
     - Log progress every 50 providers: "Geocoded 50/365 providers..."
     - Return the providers array with coordinates filled in
  </action>
  <verify>
Test geocode cache: `node -e "import('./server/geocode-cache.js').then(m => { m.setCachedGeocode('Test 1234 Bern', 46.9, 7.4, false); console.log(m.getCachedGeocode('Test 1234 Bern')); })"` — should print `{ lat: 46.9, lon: 7.4, approximate: 0 }`. Verify `data/geocode-cache.sqlite` file exists.   </verify>

Wire the complete data pipeline and connect the frontend:

1. Create `server/providers.js`:
   - Import fetchProviders, fetchPraLookup from odata-client.js
   - Import normalizeProviders from normalizer.js
   - Import geocodeAll from geocoder.js
   - Import seed data: `import seedData from './seed-data.json' with { type: 'json' };` (use import attributes syntax)
   - Maintain an in-memory variable `cachedResult` = null (the fully processed, geocoded provider array)
   - Export `getProviders()`:
     - If `cachedResult` is not null and fresh (within CACHE_TTL), return it immediately
     - Try the live pipeline:
       a. Call fetchProviders() and fetchPraLookup() in parallel with Promise.all
       b. Call normalizeProviders(rawProviders, praLookup)
       c. Call geocodeAll(normalizedProviders)
       d. Store result in cachedResult with timestamp
       e. Return the geocoded providers array
     - On error (upstream unreachable):
       a. Log the error
       b. If cachedResult exists (stale), return it (serve stale)
       c. If no cachedResult (cold start), return seedData as fallback
       d. Never throw to the caller — always return data
   - The response shape wraps providers: `{ providers: [...], meta: { count, fetchedAt, stale, seedData } }`
     - `count`: number of providers
     - `fetchedAt`: ISO timestamp of when data was fetched
     - `stale`: true if serving old data due to upstream failure
     - `seedData`: true if serving from seed-data.json fallback

2. Create `server/seed-data.json`:
   - Start with an empty array `[]` as placeholder
   - After the pipeline is working, run a one-time script to generate real seed data:
     ```bash
     node -e "import('./server/providers.js').then(async m => { const result = await m.getProviders(); const fs = await import('fs'); fs.writeFileSync('server/seed-data.json', JSON.stringify(result.providers, null, 2)); console.log('Seed data written:', result.providers.length, 'providers'); })"
     ```
   - This captures a snapshot with real geocoded coordinates
   - Commit the populated seed-data.json

3. Update `server/index.js`:
   - Import getProviders from providers.js
   - Add `GET /api/providers` route BEFORE the static file middleware:
     ```javascript
     app.get('/api/providers', async (req, res) => {
       try {
         const data = await getProviders();
         res.json(data);
       } catch (err) {
         console.error('Provider endpoint error:', err);
         res.status(503).json({ error: 'Data temporarily unavailable' });
       }
     });
     ```
   - Update the `/api/health` endpoint to include provider stats:
     ```javascript
     { status: 'ok', timestamp, providerCount: (cachedResult?.providers?.length ?? 'unknown') }
     ```

4. Update `src/main.js`:
   - On page load, fetch `/api/providers`
   - Parse the JSON response
   - Log to console: `INSOS PrA Map: ${data.meta.count} providers loaded`
   - If `data.meta.stale`, also log a warning: `Warning: serving stale data`
   - If `data.meta.seedData`, also log: `Note: serving seed data (upstream unavailable)`
   - Display a minimal message in the `#app` div: "INSOS PrA Map — {count} Anbieter geladen" (German)

5. After everything works, generate the real seed data by running the pipeline once and writing the output to server/seed-data.json (as described in step 2). The seed data should include fully geocoded providers so cold starts work instantly.
  </action>
