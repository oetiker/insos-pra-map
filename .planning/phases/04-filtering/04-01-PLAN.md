  <name>Task 1: Create filter module and export updateMarkers from map.js</name>
  <files>src/filters.js, src/map.js</files>
  <action>
**Create `src/filters.js`** with:

1. **SECTOR_MAP constant** — A grouping-rules object mapping ~14 German sector names to arrays of PrA profession name prefixes (matched after stripping the "PrA " prefix from offering names). Use the mapping from 04-RESEARCH.md Pattern 1 (Gastronomie & Hotellerie, Hauswirtschaft & Reinigung, Garten Floristik & Landwirtschaft, Bau & Gebäudetechnik, Holz & Schreinerei, Metall Mechanik & Industrie, Logistik & Transport, Verkauf & Administration, Fahrzeuge, Betriebsunterhalt & Elektro, Textil & Handwerk, IT & Medien, Gesundheit & Soziales, Uhren & Schmuck). **IMPORTANT:** SECTOR_MAP only defines the grouping rules (which prefixes belong to which sector). It does NOT determine which sectors appear in the dropdown — that is driven by the actual provider data. See step 2 and step 5.

2. **`getActiveSectors(allProviders)`** — Build the list of sectors to show in the dropdown dynamically from the data. Iterate all providers' `praOfferings`, match each profession against SECTOR_MAP prefixes, and collect only the sectors that have at least one matching provider. Any professions that don't match any SECTOR_MAP entry go into a catch-all "Weitere Berufe" sector (only shown if such professions exist). Log unmapped professions to console for maintenance awareness. This ensures the sector dropdown always reflects what's actually in the INSOS data — if INSOS adds or removes professions, the dropdown updates automatically on next rebuild.

3. **`filterProviders(allProviders, selectedSector, selectedProfession)`** — Returns the full array if no sector selected. Otherwise filters providers where at least one `praOfferings[].name` (with "PrA " prefix stripped) starts with any prefix in SECTOR_MAP[selectedSector]. If a specific profession is also selected, further requires `offering.name === selectedProfession`.

4. **`getProfessionsInSector(allProviders, sectorName)`** — Scans all providers' praOfferings, collects those matching the sector's prefixes, returns sorted unique profession names (using `localeCompare('de')`). Only shows professions that actually exist in the data.

5. **`createFilterControl(allProviders, onFilterChange)`** — Returns a Leaflet `L.Control` instance (position: 'topright') that:
   - Calls `L.DomEvent.disableClickPropagation(container)` and `L.DomEvent.disableScrollPropagation(container)` in `onAdd` to prevent map interaction leakthrough
   - Calls `getActiveSectors(allProviders)` to determine which sectors have providers, then renders a sector `<select>` with default option "Alle Bereiche" (value="") and one `<option>` per active sector (NOT per SECTOR_MAP key — only sectors with matching providers appear)
   - Renders a profession `<select>` (hidden initially) with default option "Alle Berufe" (value="")
   - On sector change: if a sector is selected, populates profession dropdown via `getProfessionsInSector()` and shows it; if cleared, hides profession dropdown and resets its value. Calls `onFilterChange(sector, profession)`.
   - On profession change: calls `onFilterChange(sector, profession)`.
   - Profession dropdown displays names with "PrA " prefix stripped for readability, but the `<option>` value is the full profession name (e.g., "PrA Küche").

**Modify `src/map.js`** to:

6. **Export `buildPopupContent`** — Make the existing function accessible so `updateMarkers` can use it without duplicating code. Change from a plain function to an exported function.

7. **Export `updateMarkers(clusters, providers)`** — New function that calls `clusters.clearLayers()`, then creates markers for all providers with valid lat/lon (same logic as in `initMap`), calls `marker.bindPopup(buildPopupContent(provider))`, collects markers into an array, then calls `clusters.addLayers(markers)`. Returns the marker count for the caller to detect zero results.

Do NOT change the existing `initMap` behavior — it still creates the initial markers.
